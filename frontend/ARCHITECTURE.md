# PropIntel Frontend Architecture

## Goals

The premium frontend is a production-oriented Next.js application that can coexist with the root Spark prototype while workflows are migrated. The code is organized around clear boundaries: app routes, feature components, reusable UI primitives, domain services, and server-only API utilities.

## Layers

```text
app/                 Route segments, metadata routes, API route handlers
components/ui/       Reusable primitives with no domain behavior
components/dashboard Dashboard shell and workspace surfaces
components/deal-twin Counterfactual investment decision simulator UI
components/planning  Planning Intelligence feature UI
lib/api-client.ts    Browser-side API client
lib/api-server.ts    Server-side API response, validation, rate-limit helpers
lib/auth.ts          JWT signing and verification
lib/session-config.ts Session constants and production secret enforcement
lib/deal-twin.ts     Deal Twin economics, gates, actions, and memo generation
lib/planning-*.ts    Planning domain data, memo generation, and formatting
scripts/             Automated local/CI checks
```

## API Standards

All Next API routes should use `lib/api-server.ts` for:

- Request ID generation and `x-request-id` response headers.
- Consistent JSON error envelopes: `{ error: { code, message, requestId } }`.
- `cache-control: no-store` on API responses.
- `x-content-type-options: nosniff`.
- Bounded JSON body parsing with content-type enforcement.
- Lightweight per-IP rate limiting for demo routes.
- Plain-text sanitization for validated string inputs.

Routes should validate every request body with Zod before calling domain services. Keep route handlers thin: parse, authorize, call a service, return a response.

## Authentication And Session Handling

- JWTs are stored only in the `propintel_session` httpOnly cookie.
- The browser does not persist JWTs in `localStorage` or `sessionStorage`.
- `JWT_SECRET` is required in production and must be at least 32 characters.
- Dashboard routes are protected by `proxy.ts` using the same issuer, audience, and cookie constants as API auth.
- Registration/login remain mock flows until the production SaaS backend becomes canonical.

## Browser Security

Global response headers are configured in `next.config.mjs`:

- Content Security Policy with production `script-src` excluding `unsafe-eval`.
- `frame-ancestors 'none'` and `X-Frame-Options: DENY`.
- `Referrer-Policy: strict-origin-when-cross-origin`.
- `Permissions-Policy` disables sensitive browser capabilities by default.
- `X-Content-Type-Options: nosniff`.

## Planning Feature Structure

Planning Intelligence is split into small units:

- `planning-console.tsx`: workflow orchestration and state.
- `betterment-signal-card.tsx`: rights-delta visualization.
- `rights-card.tsx`: single plan rights display.
- `planning-memo-panel.tsx`: memo generation/copy/download surface.
- `plan-input.tsx`: validated plan-number input UI.
- `lib/planning-database.ts`: starter data, comparison logic, memo generation.
- `lib/planning-format.ts`: display and file-name formatting.

Planning data is starter/demo data. Any professional or legal use must verify against iPlan, Mavat, or the competent planning authority.

## Deal Twin Feature Structure

Deal Twin is a counterfactual investment module that models the question: "what would need to be true for this deal to deserve capital?"

- `dashboard/deal-twin/page.tsx`: protected dashboard route.
- `components/deal-twin/deal-twin-console.tsx`: scenario controls, verdict cards, approval gates, and next actions.
- `app/api/intelligence/deal-twin/route.ts`: validated/rate-limited API route using shared API primitives.
- `lib/deal-twin.ts`: deterministic economics, stress testing, approval conditions, action generation, and board memo output.

The module is intentionally deterministic today, making it auditable and reviewable. If an LLM layer is later added for narrative expansion, keep the numeric verdict and gates generated by `lib/deal-twin.ts` as the source of truth.

## Security Checks

Run before merging:

```bash
npm run typecheck
npm run build
npm run security
```

`npm run security` runs a local pattern scan for risky constructs and `npm audit --audit-level=moderate`.
