# PropIntel Premium Next.js Frontend

A production-grade, high-end SaaS website and app shell for PropIntel. It is intentionally separate from the root Spark prototype so both can coexist while the product direction settles.

## Stack

- Next.js App Router
- React 19
- Tailwind CSS
- Framer Motion
- Custom shadcn-style primitives
- JWT-backed mock auth API routes
- PostgreSQL schema reference in `lib/schema.sql`

## Setup

```bash
cd frontend
cp .env.example .env.local
npm install
npm run dev
```

Open `http://127.0.0.1:3000`.

## Demo Auth

The login route accepts:

```text
email: demo@propintel.com
password: DemoPass123
```

Registration creates a signed mock JWT session. Replace the route handlers with the SaaS backend auth endpoints when the production API is selected as canonical.

## Production Notes

- Set a strong `JWT_SECRET` in production.
- JWT sessions are stored in the `propintel_session` httpOnly cookie; do not persist tokens in browser storage.
- Connect `DATABASE_URL` to the SaaS backend or a dedicated API layer.
- Use `lib/schema.sql` as the minimum schema shape for tenants, users, properties, and valuations.
- Keep the root Spark app available until workflows are migrated into this Next.js app.

## Deployment Checks

- `GET /api/health` returns service health for uptime monitors.
- `GET /robots.txt`, `GET /sitemap.xml`, and `GET /manifest.webmanifest` are generated by App Router metadata routes.
- Dashboard routes are protected by `proxy.ts`; unauthenticated users redirect to `/login?next=...`.
- Global and dashboard-level `loading.tsx` / `error.tsx` files provide resilient UX during route transitions and runtime failures.
- `POST /api/planning/compare` compares starter Israeli planning-rights data and returns betterment levy deltas for the dashboard planning workspace.
- `POST /api/planning/memo` generates a Markdown planning-rights memo with verification warnings and source context.
- `POST /api/intelligence/deal-twin` runs the counterfactual Deal Twin model and returns verdict, conditions, actions, and a board-ready memo.

## Differentiated Product Module

The `dashboard/deal-twin` workspace is a founder-grade decision simulator. Instead of only reporting valuation outputs, it asks the investment committee question directly: "what would need to be true for this deal to deserve capital?" It converts price, rent, capex, planning upside, debt, confidence, and risk into approval gates, counteroffer discipline, stress loss, and decisive next actions.
